# Участие в разработке

Одна задача — один pull request в `main`. Сначала опиши проблему или нужный результат в [Issue](https://github.com/gletushov/horizon/issues). Небольшую понятную правку можно прислать сразу.

## Подготовка

Нужны Node.js 22.12+ и npm; для сборки macOS нужен Mac.

```sh
npm ci
npm test
HORIZON_USER_DATA="$(mktemp -d)" npm run desktop
```

Используй отдельную рабочую папку с вымышленными данными. Тесты не должны трогать твои заметки или настоящие сессии агентов.

## Изменение

При изменении поведения: тест → ожидаемое падение → проверка качества теста → реализация → связанные проверки. Для интерфейса проверь действия в настоящем приложении и посмотри скриншоты. Документацию обновляй вместе с поведением.

Не добавляй личные документы, конфигурацию проектов, токены, логи с текстами поручений или служебное состояние. Секреты не должны появляться даже в тестовых fixtures: собирай синтетические значения в памяти.

Перед передачей проверь дифф и самый вероятный сценарий поломки. Покажи выполненные проверки и честно укажи, что осталось непроверенным. Дополнительный агент для ревью полезен, когда он доступен; обязательной платной зависимости для вклада нет.

## Pull request

Заголовок описывает результат, например `fix(notes): keep drafts after reopening the app`. Для описания используй:

- исправление: **Bug / Fix / Testing**;
- новая возможность или документация: **What / Testing**;
- большое изменение: добавь **How to read**, чтобы объяснить порядок чтения файлов.

В Testing укажи команды, результаты, реальную проверку и ограничения. Для видимых изменений приложи скриншоты на демонстрационных данных; сравнение до/после добавь, когда оно помогает оценить правку. Переработку после замечаний отправляй новым коммитом в тот же PR. Если объём поменялся, перепиши заголовок и описание под конечный результат.

Подход к PR вдохновлён [правилами Verticals](https://github.com/konstantinopolskii/verticals/pull/65). В Horizon CI запускает тесты, собирает обе архитектуры, проверяет состав пакета и работу приложения. Правила описания пока проверяет человек или агент, а не отдельный автоматический gate.
